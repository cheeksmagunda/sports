# DECISIONS log

Append-only record of every non-trivial choice. Each entry: date, area,
decision, reasoning, how to reverse. Verified facts are tagged `[verified]`;
synthesized reasoning is tagged `[reasoned]`.

Never echo credential values here. Reference creds by env var name only.

---

## 2026-05-26: Step 1 scaffold decisions

### D1: Workspace-token Railway CLI dead end (carryover from setup phase) [verified]
The `RAILWAY_TOKEN` env var holds a workspace-scoped token, which the
Railway CLI rejects for every operation (`whoami`, `link`, `up`). Use the
`use-railway` skill or hit GraphQL at `backboard.railway.com/graphql/v2`
directly. The `Makefile` has no `up` target for this reason; the `deploy`
target points the operator at the skill. Reverse: a per-project deploy
token issued by the human would re-enable the CLI; that is a Part 0.1
category-3 action (`NEEDS_HUMAN.md`).

### D2: Railway GraphQL smoke uses `projects`, not `me` (carryover) [verified]
Workspace tokens cannot resolve the `me` query. The startup script smoke
uses `projects { edges { node { id name } } }` instead. Reverse: irrelevant.

### D3: Real Sports verification deferred to first Playwright run (carryover) [reasoned]
No lightweight endpoint exists to verify Real Sports credentials without
a full JWT issuance flow. The `dev.sh` script reports presence-only and
defers true verification to the first Playwright re-auth in Step 2.

### D4: Python 3.11+, <3.13 [reasoned]
`nba_api` 1.7 (May 2026) tests against 3.11/3.12. `lightgbm==4.6.0` wheels
exist for both. 3.13 is excluded to avoid surprises on uncached wheels.
Reverse: bump `requires-python` after one full season's wheel coverage.

### D5: Polars-first, Pandas at I/O boundaries [reasoned]
Part 6.15 mandate. Polars query plans are deterministic and faster than
Pandas on the corpus sizes we ship (a single slate is ~180 rows; backfill
is ~30k rows). Pandas stays for connectors that lag (Basketball-Reference
HTML scrapers).

### D6: Pandera schemas at every module boundary [reasoned]
Part 6.7 mandate. Schema-violation aborts beat silent training on broken
data, which is the most expensive bug class. Schemas live under
`src/wnba_oracle/schemas/`; evolution diffs are logged here as they happen.

### D7: Multi-task heads (minutes / per-min rates / residual) [reasoned]
Part 6.9 + Part 4 minutes-dominance result. Single-head `real_score`
regression is the fallback path (>5% CRPS regression vs multi-task triggers
fall-back). The architecture choice is reversible at the artifact level by
training and promoting a single-head artifact.

### D8: LightGBM categorical `player_id` over per-player residualization [reasoned]
Part 6.10 mandate. Replaces the MLB Oracle per-player baseline residual
stage. Fewer moving parts; LightGBM's categorical handling is well-tested.
Cohort-pool EB shrinkage still backs the rookie tail.

### D9: Teal + magenta frontend palette [reasoned]
Part Step 9 default. Reads as league-neutral. Deep-purple + orange was
rejected because it reads as Phoenix Mercury or Lakers. Reverse: swap one
tokens file (`tokens.css` or `theme.ts`).

### D10: Free-tier Odds API, cache once per slate [reasoned]
Part 0.3 item 7. ~2 credits per slate. ~8 slates/week through the
44-game season is ~64 credits/month, well under the 500 cap. Degrade to
the most recent cached slate if usage projects over the cap. Upgrading is
a Part 0.1 category-3 spending decision.

### D11: Low-data mode if labeled corpus <2000 rows [reasoned]
Part 0.3 item 6. Heavier shrinkage, fewer trees (200 vs the MLB 400),
fewer leaves (15 vs 31), wider conformal bands, transparent heuristic
picker as serving fallback. The two thresholds live in `configs/models.yaml`
once that file is generated by Step 6.

### D12: Determinism gate via byte-equal pickle SHAs [reasoned]
`OMP_NUM_THREADS=1`, fixed seeds in numpy/lightgbm/random, exact pins on
`numpy==2.2.6` and `lightgbm==4.6.0`. `Makefile` `determinism-check` runs
the gate locally; CI runs the same gate before promotion.

### D13: Mondrian CQR with cohort splits Guard / Forward / Center [reasoned]
Part 6.3 mandate. WNBA position taxonomy is simpler than MLB
(no bullpen split). `mapie` is the chosen impl; ~80 LOC fallback in
`src/wnba_oracle/eval/conformal.py` if `mapie` proves rigid.

### D14: Monotonicity constraint set [reasoned]
Part 6.4. Constraints: mins_l5/l10/pred_minutes (+1), usg_pct_l10 (+1),
opp_def_rtg (+1), is_back_to_back (-1), vegas_total (+1),
implied_team_total (+1). Constraints regularize and make SHAP audits
interpretable. Reverse per-feature by editing
`configs/models.yaml::monotone_constraints`.

### D15: Picker is a lineup optimizer, not a top-5 sort [reasoned]
Part 1.3. Two-stage: filter to top-30 by `pred_real_score * card_boost`,
then enumerate `C(30, 5) = 142506` lineups and score each by
`E[payout(lineup_score)]` against a simulated field. Joint sampling via
Gaussian copula on log-residuals. Budget: 30s per slate.

### D16: Default to top-20 payout regime when unknown [reasoned]
Part 1.2 fallback. Convex above the line, some variance is good. Probed
schedule swaps this default at Step 2.
